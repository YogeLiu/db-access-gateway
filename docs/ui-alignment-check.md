# 布局回归检查

此前自动验证仅覆盖 TypeScript 编译与后端，没有浏览器布局断言。
本次浏览器连接不可用，以下记录源码确认的复现、修正与待人工验收项；不将构建成功等同于视觉验收。

1. 管理员打开字段脱敏，选择数据库，使搜索框、数据表下拉框显示。
   修正前：工具栏 align-items:center 将单行搜索框与含标签的下拉框整体居中，输入边缘错位。
   修正后：专用 maskingToolbar 使用底部对齐、相同 36px 控件高度，支持换行。
   验收：桌面上三处输入底边齐平；窄屏纵向排列，无溢出。
2. 用户打开安全设置。
   修正前：面板和表单仅限制 max-width，默认靠左。
   修正后：面板及 440px 表单均 margin-inline:auto，标题居中，字段标签保持左对齐。
   验收：面板在内容区居中，表单在面板内居中，移动端不溢出。
3. 新建 Token 不选择有效期，关闭弹窗后检查列表和页面下方配置。
   验收：Token 显示永久有效；眼睛图标切换明文，配置仍仅引用 DB_ACCESS_TOKEN。
   删除确认后条目消失，刷新仍不展示；历史已撤销条目也可删除。
   下方两份配置常驻，各有复制按钮，即使没有 Token 也能复制变量模板。
   已撤销或过期 Token 不可查看原文，跨用户读取与删除由接口拒绝。
4. Token 列表采用分隔线布局；首行左侧名称，右侧固定“状态、眼睛图标、删除”。
   凭证及创建/到期时间在下方；眼睛不再放在凭证下面。
   组件结构测试验证状态、图标和删除在同一操作容器，失效 Token 没有明文开关。
   人工视觉验收：桌面与窄屏上操作保持同行，长名称/Token 自动换行，不横向溢出。
   MCP 两份配置保持直接可见，标题右侧复制，环境变量说明按需展开。
